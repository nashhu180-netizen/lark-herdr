# 飞书轻量桥接 HerdR

编写时间：2026-09-11。
目标：当天在原生 Linux 跑通最小 MVP。
状态：设计确定；HerdR 命令、参数、输出及状态语义均须本机验证。

## 1. 范围

一个飞书会话绑定一个 HerdR workspace 中的一个已有编排 Agent。多个飞书会话分别绑定不同 workspace，互不影响。普通文本直接提交给绑定的原 Pane Agent，保留其原有上下文。

支持列出 Agent、绑定目标、手动读取输出，以及经确认后创建 workspace 并启动 Codex 或 Claude。创建成功后绑定新目标，后续任务说明通过普通文本发送。

仅连接一个明确配置的 HerdR 实例。手机无需直接连接 Linux，也不开放公网入站端口。

## 2. 最小架构与技术选型

通信路径：

手机飞书 → 飞书长连接 → Python 桥接进程 → HerdR CLI → 指定 workspace / Pane Agent。

选择 Python 3.11+。唯一直接第三方依赖使用飞书官方 Python SDK `lark-oapi`，固定为本机验证过的版本。其余使用标准库：`sqlite3`、`subprocess`、`threading`、`pathlib`、`logging`。

桥接只有一个常驻进程。SDK 负责长连接收发，同进程工作线程处理业务，HerdR CLI 作为短命子进程调用。SDK 回调不得等待 CLI 执行。

使用一个全局非阻塞执行锁，最多处理一个短操作；繁忙时立即回复，请用户稍后重发，不建立等待队列。锁只覆盖桥接操作，不等待 Agent 完成任务，各 workspace 内的 Agent 仍可并行工作。

代码只划分三个职责：飞书接入、业务路由与 SQLite、HerdR 薄适配层。不引入 Web 服务、消息中间件或插件机制。

## 3. 绑定与持久化

SQLite 是绑定和操作结果的唯一持久化来源。使用短事务，外部 CLI 调用不占用数据库事务。

### 3.1 绑定记录 `bindings`

| 字段 | 含义 |
|---|---|
| `chat_id` | 主键，飞书群聊或私聊会话 ID。 |
| `herdr_instance` | 启动时固定并验证的 HerdR 实例标识。 |
| `workspace_id` | workspace 的实际 ID。 |
| `pane_id` | 编排 Agent 所在 Pane 的实际 ID。 |
| `agent_kind` | `codex` 或 `claude`。 |
| `agent_instance` | 可核验的 Agent 实例标识，来源待本机验证。 |
| `revision` | 每次绑定或换绑递增。 |
| `bound_at` | 本次绑定生效时间。 |
| `bound_by` | 操作者的飞书 `open_id`。 |

`agent_instance` 优先采用 CLI 暴露的会话实例标识；若只能取得 PID，须结合进程启动时间，避免 PID 复用。无法核验目标实例时，禁止投递。

约束：

- 一个 `chat_id` 只有一个当前绑定；同一 HerdR 实例中的一个 workspace 最多绑定一个飞书会话，通过数据库唯一约束保证。
- 名称仅用于显示，路由始终使用实例、workspace、Pane 和 Agent 实例标识。禁止依赖桌面焦点、当前 workspace 或模糊名称。
- 每次读取或投递前重新核验目标归属及实例。目标消失、被替换或无法识别时，绑定失效，要求重新 `/bind`，不得自动寻找替代 Agent。

### 3.2 操作记录

另设两张表：

| 表 | 最小内容 |
|---|---|
| `requests` | `message_id` 主键、会话、操作者、动作、绑定版本、目标快照、状态、简短结果、更新时间。 |
| `create_requests` | 请求 ID、确认码、会话、发起人、项目目录快照、Agent 类型、workspace 名称、原绑定版本、过期时间、状态、已创建的目标 ID。 |

普通操作状态只使用 `processing / done / failed / unknown`。创建请求额外具有 `pending` 状态；取消或过期后不可执行。

默认不持久化消息正文、完整终端输出和密钥。进程重启后保留绑定，但首次使用仍须重新核验目标。未结束的操作统一标记 `unknown`，不自动续跑。

## 4. 飞书命令与交互

群聊仅处理白名单用户明确 @ 本机器人的文本；私聊直接处理白名单用户文本。剥离本机器人的提及后，再识别命令或正文。忽略机器人自身消息、非文本消息和编辑事件。

以下均为桥接命令，不代表 HerdR 原生命令。

| 输入 | 行为 |
|---|---|
| `/agents` | 按 workspace 列出允许访问的 Agent，展示 workspace ID、Pane ID、类型、状态及是否已被其他会话绑定。 |
| `/bind` | 显示本会话当前绑定及有效性。 |
| `/bind <workspace_id> <pane_id>` | 核验目标后建立或替换绑定。目标已被其他会话占用则拒绝。 |
| `/read` | 读取绑定 Pane 最近输出，最多 80 行、3000 字符；截断时明确提示。 |
| `/new <项目别名> <codex或claude>` | 生成待确认创建请求，尚不创建任何资源。 |
| `/confirm <确认码>` | 执行本会话内、同一发起人的有效创建请求。 |
| `/cancel` | 取消本会话尚未执行的创建请求，不中断已有 Agent。 |
| 其他普通文本 | 提交到本会话绑定的原 Pane Agent。 |

未知的 `/` 命令只返回帮助，不透传给 Agent。未绑定时，普通文本返回绑定提示。

### 创建确认流程

`/new` 仅接受配置中的项目别名。目录由配置映射为固定绝对路径，workspace 名称由项目别名和请求 ID 自动生成。

确认消息必须显示：项目实际路径、workspace 名称、Agent 类型，以及成功后将替换哪个会话绑定。确认码有效期为 5 分钟，只能使用一次；同一会话的新请求使旧的未执行请求失效。

`/confirm` 执行顺序：

1. 核验会话、发起人、有效期、项目路径和原绑定版本。绑定已变化则要求重新 `/new`。
2. 在事务中将请求从 `pending` 改为 `processing`，阻止重复确认。
3. 创建 workspace，立即记录明确返回的 workspace ID 和根 Pane ID。
4. 在该 Pane 启动指定 Agent，再读取实际状态，核验类型和实例标识。
5. 全部成功后，以事务替换绑定并记录完成；旧 workspace 保持原样。

任一步失败都不修改原绑定。已创建但未完成启动的 workspace 保留，并回报其 ID，不自动删除。创建或启动结果不明时标记 `unknown`，禁止自动重试及重复确认，先人工核对现场。

## 5. 投递、去重与重连

收到消息后先检查会话和操作者权限，再按飞书 `message_id` 去重。已处理消息只返回原操作状态，不再次调用 HerdR。

接受操作时固定绑定版本和目标快照；实际执行前再次核验。发生换绑或实例变化即拒绝，不将原请求改投新目标。早于当前绑定生效时间的迟到普通消息也拒绝；消息时间无法解析时不投递。用户应在收到绑定成功回执后发送任务正文。

普通文本只有在目标处于本机验证过的可接收 prompt 状态时才提交。运行中、权限菜单、无法识别的交互状态均不强行输入，返回状态并提示 `/read`。不排队、不自动按确认键。

调用前持久化 `processing`，调用后保存结果，再发送飞书回执：

- 明确提交成功：回复目标名称及 `已提交，尚未确认任务完成`。
- 明确未提交：记录 `failed` 并回报原因。
- CLI 超时、执行中进程退出或投递结果无法确认：记录 `unknown`，不重发。

CLI 超时后终止并回收子进程，但不能据此断言 HerdR 尚未收到请求。

长连接交由 SDK 重连；SDK 无法恢复并退出时由 systemd 重启桥接。连接恢复不重放数据库中的业务操作，飞书重复投递仍按 `message_id` 去重。

飞书回执发送失败只记录状态，不重新执行 HerdR 操作。MVP 不保证消息必达，也不宣称严格一次执行；采用结果不明时停止自动重试的策略，优先避免重复副作用。

## 6. HerdR 薄适配层与本机验证

业务层只使用六项能力：列出 Agent、解析并核验目标、读取输出、提交文本、创建 workspace、启动 Agent。

所有 HerdR 命令拼装、输出解析、实例识别和状态映射集中在适配层。输出统一为明确的目标 ID、实例标识及 `ready / busy / needs_attention / unknown` 等内部状态。

使用绝对路径调用可执行文件，参数以数组传递，`shell=False`。查询默认超时 5 秒，投递、创建和启动默认超时 15 秒。超时只表示调用结果不明。

**下表所有命令族、参数及输出均待本机验证，上一轮讨论不能作为验证依据。**

| 能力 | 候选命令族 | 必须本地实测的内容 |
|---|---|---|
| 版本及定位 | `herdr --help`、版本查询及子命令帮助 | 记录安装版本；确认如何显式选择固定实例，操作不依赖桌面焦点。 |
| 列出和解析 | `herdr workspace list`、`herdr agent list`、`herdr agent get` | 实际命令是否存在；workspace、Pane、类型、目录、实例和状态字段如何取得。 |
| 提交文本 | `herdr agent prompt` | 精确指定目标的方法；普通、中文、多行及前导连字符文本如何安全传入；返回值能证明什么。 |
| 读取输出 | `herdr agent read` | 目标参数、行数参数及实际输出格式；验证文本或 JSON，不预设格式。 |
| 创建空间 | `herdr workspace create` | 指定目录和名称的实际参数；能否明确得到新 workspace 及根 Pane ID。 |
| 启动 Agent | `herdr agent start` | Codex、Claude 类型值及目标参数；启动后如何核验实际进程和实例。 |

另外必须实测：Agent 退出、Pane 被替换、workspace 被删除、HerdR 重启，以及权限菜单出现时的行为。尤其要确认提交操作自身能够拒绝已失效的 Agent 目标，避免检查后目标退出导致文本进入 Shell。

不得假定 `--json`、`--session`、`--kind` 等参数存在。仅支持本机已验证版本，保留脱敏输出样本；解析失败立即拒绝操作。

若无法可靠定位目标、核验 Agent 或安全提交文本，停止投递能力验收，不降级使用当前 Pane 或裸终端输入。若创建接口无法返回可靠 ID，仅禁用 `/new`，不得通过选择最新 workspace 猜测目标。

## 7. 最小安全边界

配置固定的飞书用户 `open_id` 白名单、会话 `chat_id` 白名单和项目目录别名。三者均采用默认拒绝策略；列出与绑定也只能访问配置允许的项目。

用户输入不得决定可执行程序、任意目录、CLI 选项或权限模式。拒绝终端控制字符，保留正常文本换行。禁止任意 Shell 执行、按键注入和跳过 Agent 权限确认。

创建确认只授权建立 workspace 和启动 Agent，不授权后续危险操作。Agent 需要权限确认时由用户通过原终端处理。

每条回执带目标 workspace 和 Agent 标识。`/read` 会将终端内容发到对应飞书会话，群成员可见；不得把含敏感内容的项目绑定到不适合的群。

## 8. Linux 运行

使用与 HerdR 相同的普通 Linux 用户运行桥接，避免跨用户访问终端和套接字。前置条件是 HerdR、Codex、Claude 已在本机正常工作，模型登录和首次交互初始化已完成。

配置分为：

- `~/.config/feishu-herdr-bridge/config.json`：HerdR 可执行文件与实例选择信息、用户及会话白名单、项目别名、超时。
- `~/.config/feishu-herdr-bridge/credentials.env`：飞书应用凭据，权限 `0600`，不进入仓库。
- `~/.local/state/feishu-herdr-bridge/bridge.sqlite3`：绑定与操作状态；目录权限 `0700`。

以一个 systemd 用户服务运行，异常退出自动重启，日志写入 journald。使用本机进程锁防止同一配置启动两个桥接实例。需要退出登录后持续运行时启用用户 linger，并实测。

主机须保持供电、禁止自动休眠、保持时间同步及到飞书和模型服务的网络连通。桥接不负责启动或重启 HerdR，不保证主机重启后原 Agent 进程恢复。

飞书侧必须本测：机器人可接收事件并发消息、长连接初始化、会话与操作者字段、消息 ID 与创建时间、@机器人识别、重连和重复事件处理。事件接入候选为 `im.message.receive_v1`，实际 SDK 调用以安装版本验证结果为准。

## 9. 验收标准

| 场景 | 通过标准 |
|---|---|
| 双会话隔离 | 群 A 绑定 workspace A，群 B 绑定 workspace B；分别发送不同测试标记，只有对应原 Pane 收到。 |
| 焦点与名称干扰 | 切换桌面焦点、使用相似 Agent 名称后，投递与读取目标仍正确；同一 workspace 被另一群绑定时明确拒绝。 |
| 换绑与目标失效 | 换绑后重投旧消息、延迟送达旧消息，以及 Agent 退出后再次投递，均不进入新目标或 Shell。 |
| 去重与异常 | 同一 `message_id` 重复到达只提交一次；CLI 超时或桥接执行中退出后，不自动重做结果不明的操作。 |
| 创建确认 | 未确认、错误确认码、过期确认、其他用户确认均不创建；分别验证 Codex 和 Claude 创建成功并正确绑定。 |
| 创建部分失败 | workspace 已创建但启动失败时保留旧绑定并报告资源 ID；重复确认不创建第二个 workspace。 |
| 移动端实际使用 | 手机移动网络下完成列出、绑定、发送和读取；桥接重启及飞书重连后，绑定可重新核验使用，原有任务不受影响。 |
| 安全拒绝 | 非白名单用户或会话、任意项目路径、未知命令和控制字符均被拒绝，不触发 HerdR 写操作。 |

先验收已有 Agent 的双会话隔离，再验收创建能力。未经对应本机实测的能力不得标记可用。

## 10. 非目标

本版不做自动巡检 workspace、总监控 Agent、自然语言控制命令解析、自动拆任务、多 Agent 编排、任务队列、主动完成通知或持续输出推送。

不支持 `/clear`、审批代点、文件上传下载、网页前端、多主机、多 HerdR 实例、插件系统或远程 Shell。

飞书负责发指令和按需读输出；现有编排 Agent 继续承担任务内部协作。
