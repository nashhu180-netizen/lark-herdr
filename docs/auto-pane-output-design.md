# 绑定主控 Pane 的有限自动回传

编写时间：2026-09-12。状态：`AUTO_OUTPUT_DESIGN_REV2_READY_FOR_LOCAL_REVIEW`。本轮仅设计，未实现或运行新的验收。

基线为 `main@0de93b578f28f5cbe9b20dff70a7a6b146ba2981`；Issue #7 / Draft PR #8，分支 `feat/auto-pane-output`，起始提交 `b727245e5a2b130af7547ad6520c762f2c2eea80`。已读取 core、HerdR/飞书适配、SQLite、runtime、相关测试与 runbook。199/199 和 Devin 冒烟属于上一轮本地证据，不代表本功能通过。[R1][R2]

## 1. 选择：每个源提示限时观察，支持连续多轮对话

第一版为每条成功提交的群内普通文本独立启动观察：保持现有提交回执，每轮最多观察原绑定 Pane 120 秒，取得稳定、可明确区分的新正文后，向原群自动补发一条。支持同一群、同一绑定主控 Pane 的连续多轮顺序对话，无需重新绑定或重启。保留 `/read`；不做逐 token 推送、持续终端镜像或长任务后台守候。

自动消息是原 Pane 的文本片段，不调用 LLM、不改写或总结，不给 Agent 附加输出格式要求、隐藏提示、轮询提问或文件写入任务。观察只执行 `agent get/read`，不额外触发模型请求。主控自己显示的正常输出可以回传，桥接不读取其他 Pane，也不主动抓取其工作线程或子 Agent 的会话。

“最多一次”按成功提交的源 `message_id` 计数，不是每群或每个绑定的累计额度。第一轮提示 P1 的观察 consumed 后，第二条新普通文本 P2 成功提交时必须获得独立观察机会，可自动回传第二条不同正文 A2；不得因该群或 revision 已发送过 A1 而关闭后续回传。此能力仍不能承诺网络上的严格一次且必达。超时、输出来源不明或不确定发送优先丢弃，用户用 `/read` 兜底。不能把“没有自动消息”解释成 Agent 没有执行。

固定 `kpi-agg`、三种 Agent、用户/群授权、workspace 独占、绑定 revision、提示幂等、失效绑定、建群及 Devin 创建均沿用当前实现。管理群没有特殊观察权限；只有具有有效绑定的真实群聊可以触发自动回传，私聊和全部斜杠命令维持原行为。

## 2. 最小架构与资源上限

新增一个 `output.py`，放置确定性快照提取、临时观察记录和观察循环。单进程内增加一个可停止的观察线程；多个群只有各自的内存记录，不按群创建常驻线程，不增加队列、数据库表、事件总线或插件。

| 项目 | 固定上限与语义 |
|---|---|
| 同时观察 | 最多 16 个群，每群同时最多一个活动观察；上一轮结束后释放槽位，后续新提示可再次使用。满额时本次提示仍正常提交，只跳过自动回传，不驱逐其他群。 |
| 生命周期 | 每个成功提交的源提示从自身提交确认时开始，以 monotonic 时钟独立计时 120 秒；忙碌或跳过采样不延长，不继承上一轮剩余时间。 |
| 采样 | 每条记录最快每 2 秒检查一次，最多 60 轮，按到期顺序轮转；争用时跳过，不积压待办。 |
| 读取 | 只取 `visible`、80 行、`text`；单份快照超过 32 KiB UTF-8 即停止自动提取，不保留截断基线；提示超过同一预算也只跳过自动回传。 |
| 超时 | 观察用 get/read 每次最多 2 秒；自动消息 HTTP 使用有界超时，单次发送等待最多 3 秒，不重试。 |
| 稳定性 | 新正文在两个相隔至少 2 秒的有效采样中一致，且两个采样均为 `idle/done`，才可发送。 |
| 自动消息 | 每个成功提交的源提示最多一条自动消息；不同新提示分别计数。含 Pane 标识及必要截断尾行不超过 3000 个 Unicode 码点及 80 行，不分包补发。 |

复用现有非阻塞操作锁和同一个 `ManagedRunner`。观察可使用同类、同 executable/session/runner 的只读适配实例，把查询超时限制为 `min(原 query_timeout, 2 秒)`，不临时改写前台适配器参数，不另开 CLI 服务。轮询不调用 `agent list`、workspace/tab list，也不扫描全部绑定。[R3]

没有记录时只等待唤醒。每轮短操作结束就释放锁，绝不持锁睡眠或等待整轮 Agent 任务。前台持锁时观察跳过；观察占锁时用户消息仍遵循原有 busy 拒绝语义。多群负载下 2 秒是最短间隔，不是延迟承诺。

## 3. 提交与观察的关联

内部观察键固定为 `(源 message_id, chat_id, herdr_session, workspace_id, pane_id, binding_revision)`，并保存原操作者、机器人身份、Agent kind、随机 `watch_ref` 与过期时间。绑定名称和当前桌面焦点不参与路由。`watch_ref` 和观察记录携带的 revision 仅供内存守卫及脱敏日志使用，不出现在飞书提交回执、自动正文或兜底说明中；原有绑定 revision 的持久化机制保持不变。

在 core 已完成原有授权、幂等、时间和绑定校验之后，紧邻实际 `agent prompt` 调用前，执行可选的基线捕获。只对当时为 `idle/done`、kind 已支持且未超容量的目标捕获一次可见快照 B。这发生在同一个前台操作锁内；捕获失败只使本次自动回传不可用，不吞掉、替换或重发原提示。原 prompt 仍由既有 Agent 接口作提交时校验。

同群已有观察时，在新的普通提示真正准备提交前取消旧观察；即使新提示后来提交失败，也不恢复旧观察。如果该 Pane 此时仍 `working/blocked/unknown`，本次不启用自动回传，输入是否可以提交仍由原逻辑决定。这样不把上一轮工作的结果挪给下一条提示；第一版优先服务同一 Pane 的顺序交互。

只有以下条件全部满足才正式注册观察：原 prompt 明确提交成功、原 `requests` 已记录 `done/submitted`、绑定仍匹配捕获版本、当前授权有效。注册在原操作锁释放前完成；任何辅助观察异常不得修改已确认的提示提交结果。提示超时、结果不明、消息级落库失败、重复事件、重复确认、`/new` 启动成功均不能注册观察。[R4]

连续两轮时，P1 结束只关闭其自身记录。P2 使用新的 `message_id`，在其实际提交前重新捕获当前基线 B2；B2 中的 P1/A1 属于历史，不进入 P2 的新正文。P2 重新初始化候选、稳定计数、hash 和 120 秒期限，即使 chat/Pane/revision 都没变化，也必须可以独立回传 A2。旧记录清理只作用于自身完整观察键，不能删除新一轮记录；相同旧 `message_id` 重投仍不能重新注册。

普通提交回执保持原代码 `submitted` 与简短提交确认，不回显提示或增加逐轮调试信息；无法注册时仅提示“本次自动回传未启用，可用 /read”。120 秒及提取限制在 runbook 说明，不逐轮重复。无需等待回执送达才开始观察；回执发送失败不重新提交提示。

## 4. 新正文提取与去重

### 4.1 只用被动可见快照

沿用现有参数：`<absolute_executable> --session kpi-agg agent read <original_pane_id> --source visible --lines 80 --format text`。不切换 recent/history，不滚屏、不 focus、不注入按键。官方文档说明某些 recent 读取会操作全屏 Agent 的滚动视图；本轮避开该行为。状态只用来选择采样时机，不视为精确的模型轮次编号。[R3][R7]

快照不是可靠的增量日志。不能把“最后一屏减去公共前缀”无条件当作回答，也不能用全屏 hash 改变就发整屏。一个快照可能同时包含旧对话、用户回显、banner、输入框和状态栏。

### 4.2 有界、正向识别的提取规则

在 `output.py` 内用少量固定规则识别当前三种 CLI 的内容区域及用户/输出块；不暴露可配置模板、注册表或插件接口。规则须由可审查的脱敏快照样本支撑，不能仅因 `agent.kind` 已识别就假定 UI 格式也已支持。未知布局返回 `unrecognized`，绝不回退为发送原始整屏。

提取器只做以下确定性工作：

1. 统一 CRLF 为 LF；保留正文缩进、内部空行、多行 Unicode 和可见软换行，不改词句、不重排段落。`--format text` 之后仍出现无法解释的终端控制序列、独立 CR 或不完整边界时拒绝提取。只在已识别的 UI 区域移除 banner、输入框、边框、状态行，不对正文全局删除 `>`、项目符号或含某些关键词的行。
2. 把基线 B 和候选 S 转成按屏幕顺序排列、带来源区间的内容行及用户/输出块。若 S 以完整 B 开头，新区域从 B 末尾开始；否则求满足 B 的最后 k 行等于 S 的前 k 行的最大 k，该段至少含两行非空内容，且整个锚点序列在 B、S 内各只出现一次。新区域从 S 的第 k 行之后开始。锚点重复、清屏、重排或重叠不足时放弃本次自动正文，不用宽松字符 diff 补猜。基线内容区明确为空时允许从空边界开始。
3. 在证明为新的区域中，必须出现且只出现一次与本次提示完全对应的完整用户块。只移除已知 UI 包装和行尾填充后比较；不折叠正文内部空白，不用子串匹配。完整多行提示或换行方式无法核对、同一提示的旧回显被当作候选、新区域中发现另一个用户输入块时拒绝。本轮基线已包含的上一轮用户块和正文属于旧区域，不能因此拒绝正常第二轮，也不能再次转发它们。禁止追加随机标记到真实用户提示以帮助匹配。
4. 只取该新用户块之后、已识别的 Agent/CLI 正文块；用户块、工具执行面板、审批 UI、输入提示、banner 和 chrome 不纳入候选。没有明确正文边界就不自动发送。候选只是提示回显或与规范化后的提示完全相同，也不发送。
5. 在 `working` 时不积累正文，不推进已发送游标；回到 `idle/done` 后对照最初 B 重算候选。候选两次稳定再发送，期间改变则重新等待。这样不会逐次复读增长中的同一行，也不用维护屏幕翻页日志。没有观察到 `working` 的快速响应也须通过新用户块与增量证明，不能仅凭 `idle` 发送旧回答。

显示只覆盖当前可见、可证明的新正文。超过 80 行导致用户块或重叠锚点滚出、窗口 resize、复杂全屏重绘、无法辨认的软换行都可能只得到兜底提示。这是本版明确的体验限制，不承诺完整历史或完整长答案。

当前仓库只有合成读取示例，没有足以证明三种 UI 分界的完整多帧样本。O1 必须交付正负样本和实际采用的精确边界规则；本地未核对的 CLI 布局保持不可提取，不能把假样本通过记为 live 支持。优先核对指定 Devin 验收 Pane；不能为搜集样本访问其他 KPI Pane。

### 4.3 一条消息的形成

每个源提示的临时记录只保留本轮 B、当前/上次候选以及在本进程内比较用的 hash；不用历史输出库。相同快照、候选尚不稳定、空候选均不发送。去重状态以源提示为界，不把该群或绑定的“曾发送”标志沿用到后续轮次。

自动回复只显示一行 `主控 Pane <pane_id>`，换行后按原顺序复制本轮正文；不显示 `watch_ref`、revision、源消息 ID、轮询次数或其他调试字段。超长时预留 Pane 标识及尾行 `[已截断；可用 /read 查看当前画面]` 的预算，从开头保留正文：先按行限截取，末行需要时按 Unicode 码点截，不切 UTF-8 字节。不能为被省略的尾部继续补发。未截断时不添加截断标记，不把此消息命名为“任务已完成”。兜底说明也只带同一 Pane 标识和一句说明。

一旦领取发送机会，该源提示的记录即进入 `consumed`，发送尝试结束后无论成功或失败都结束本轮并释放槽位。同一源提示没有第二个自动正文发送机会，后续新的成功提示仍可重新捕获基线并发送一次；不能把 consumed 作为整个群或绑定的终态。用户显式 `/read` 的新请求不属于自动重发。

## 5. revision 守卫与发送边界

每次观察先取得操作锁，再读 SQLite 当前绑定和原用户/群授权。只有 `valid=true` 且原 chat/session/workspace/pane/revision 全匹配、当前 bot 身份相同、原操作者仍获准，才允许调用原 Pane 的 get/read。HerdR get 还须验证 workspace、Pane 和捕获 kind。读取完成后再次核对，发送前再核对一次。

输出绝不通过 `core.handle` 当成用户输入，避免反馈循环。也不能重新查询“当前群应该发给哪个 Pane”后更换目标；目标 chat 永远来自原记录。成功 `/bind` 到同一 Pane 也会增加 revision，旧观察因此失效；workspace 创建导致的换绑同理。跨群转移 workspace 后旧观察只会丢弃，不能改投新群。

同群手动 `/read` 开始执行时取消尚未消费的观察，但 `/read` 原有读取、授权、错误与回执内容保持不变，避免读完又收到同一自动片段。其他命令不启动观察；`/cancel` 继续仅取消既有提案，不被改造成 Agent/观察控制命令。

自动输出新增独立的有结果的 `send_output_once` 边界，不复用当前 `send()` 的异步入队即返回语义。[R5] 由观察线程同步等待一次发送结果，使用现有 text 消息构造和 tenant 身份；实际消息 POST 禁止 HTTP 重定向及 SDK/HTTP 隐式重试，须用固定 SDK 的实际 HTTP 边界测试证明。

取得最终守卫后，在同一操作锁内先标记 consumed、记录发送尝试，再发出一次 POST，直到有界返回才释放锁。不把正文排入可延迟发送的旧回执队列，防止通过检查后又被重绑。SQLite 事务不跨网络等待；其他前台命令在这段短时间按原 busy 规则处理。

锁约束的是通过桥接进行的绑定变更，不支持运行中外部改库。已开始的远端 HTTP 无法撤回，确认未知的旧消息可能较晚出现在原群；其目标 chat 和显示的 Pane 标识始终冻结为原值，不能改投新群或改标为新 Pane。原 revision 留在内部审计中，不为排障加到群消息。不能承诺撤销已进入飞书的消息、晚到消息的跨轮到达顺序或跨系统原子发送。

## 6. 停止、错误与持久化选择

本轮不改 `store.py`、不迁移 schema，保持 v2 四表。观察内存状态只有捕获、观察、已消费、已关闭及受控关闭原因；不持久化原始快照、候选、用户提示或可被字典猜测的内容 hash。

| 情况 | 处理 |
|---|---|
| `working` | 继续有界状态观察，不发送变化中的画面，不询问 Agent。 |
| `idle/done` | 按正文新旧边界和双采样稳定规则处理；状态本身不能证实完成。 |
| `blocked/unknown` 或未识别状态 | 停止正文提取，不代点确认；绑定仍合法时最多发一条无原始内容的说明，提示人工检查并 `/read`。 |
| Pane 消失、get/read 失败或超时、workspace 不符 | 停止观察；沿用读取失败的保守策略，以原 snapshot 调用条件失效，不能使更新后的绑定失效；无裸 Pane/Shell 回退，不发送读到一半的正文。 |
| 绑定版本/授权/bot 变化 | 无内容、无提醒，直接丢弃；不刷新成新绑定继续工作。 |
| 120 秒结束、解析不可靠或无可证明的新内容 | 停止；绑定和授权仍匹配时，最多发一次固定说明“本次自动回传已停止，可用 /read 查看当前画面”，不发送旧屏或猜测片段。 |
| 飞书拒绝、超时、断连、回执缺失 | 自动发送状态记为 failed/unknown 并结束，不重试消息或原 prompt；不因此使有效绑定失效，不改变原 requests 的提交成功状态。 |
| 新的实际提示、手动 `/read` | 先撤销同群尚未发送的观察，不影响其他群。 |

发送成功、失败、未发送取消和进程中断都不通过扫描旧 `requests` 恢复。每次 bridge 启动观察集合为空；只有本进程新完成的真实提示投递能注册。原 message_id 重投只走现有重复结果，不重新捕获 B，也不注册观察。下一条新提示重新取基线排除旧屏；新轮次若无法识别仍只兜底，不补齐停机期间输出。

审计仅在现有 journald 写随机 `watch_ref`、原绑定 revision、事件类型、原因码和计数，例如 armed/attempted/sent/unknown/cancelled。这些内部标识不进入飞书消息；日志不含实际 chat/user/message ID、群名、确认码、提示、正文、hash 或原始异常。两轮各有独立观察记录供内部核对，不能要求用户通过调试编号区分回复。只有 armed/attempted 而没有终态的历史日志视为中断/未确认，不能据此自动重发；不新增日志存储或补偿任务。

退出先关闭接收、标记观察停止，丢弃未发送候选并唤醒观察线程；复用 `ManagedRunner.stop` 回收当前读取子进程，有界等待线程退出。停机不把最后一屏作为结果强行发送。已发出的飞书请求可能仍送达，既不撤回也不在重启后重发。[R6]

## 7. 敏感内容与非目标

自动回传扩大了已授权群成员看到该 Pane 内容的时机；授权不等于自动脱敏。不能保证识别正文内所有密钥或私人信息。只应在适合该群可见范围的主控 Pane 使用；UI 清洗只去回显和界面元素，不能把它宣传成安全内容审查。内存原文在记录结束时释放，不写文件，不进日志或测试证据。公开 fixture 使用合成/脱敏数据。

不做全屏实时镜像、滚动历史抓取、结构化会话日志接入、进程指纹、LLM 总结、子 Agent 聚合、全仓/全 session 监控、主动推进任务、自动审批、重新生成回复、文件/图片回传、新命令、额外配置系统或持久化 outbox。

同一 Pane 在观察期间由本地终端或其他客户端插入新提示、替换同种 Agent，现有接口无法提供完整轮次归属证明。发现不同用户块/格式或 kind 改变就停止；相同 Pane/相同 kind 的无可见替换不宣称可检测。可靠体验的前提是观察期间该主控按顺序接受飞书提示。更复杂并发对话留到独立需求。
